# LRM Server

## Development Setup

- Copy the `.env.template` and rename it `.env`:

```bash
cp .env.template .env
```

- Set the value of `LRM_PASSPHRASE` to the passphrase of the server certificate to conect to RabbitMQ. Ask for the value to another member of the team.

- *Optional:* Update the content of the `.env` file:
  - `HUB_URL` controls the RabbitMQ instance the app will connect to. Use `amqps://messaging.<environment>.hub.esante.gouv.fr` to connect to a specific environment (or `amqps://messaging.hub.esante.gouv.fr` for production).
  - `GITHUB_TOKEN` is used to interract with Github API. It should be set to a valid token when working of the feature that consumes the Github API. See [Github documentation](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens) on how to generate a personal token with the correct rights.
  - `ADMIN_PASSWORD` controls the password that the user in the client should provide when using admin feature (like auto-commit to Github).
  - `VHOST_CLIENT_MAP` controls on which queues the server will connect on the RabbitMQ instance. Format is map with vhost as key and and array of clientIds as value.
  - `PORT` controls the port the Express app is listening to (default 8081).
- Install dependencies

```bash
npm install
```

- Start with hot reload (available at [localhost:8081](http://localhost:8081))

```bash
npm run dev
```

*Note: as all other clients connecting to RabbitMQ, the LRM server uses a certificate available in [src/rabbit/certs/](src/rabbit/certs/)*

### Tests

Unit tests implemented using vitest.
Use `npm run test` to run them (coverage is generated by default).
